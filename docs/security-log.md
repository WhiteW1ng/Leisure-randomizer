# Журнал безопасности — пара 8

## Журнал и хранение

Security-события записываются Laravel в отдельный ежедневный журнал: `my-site/storage/logs/security-YYYY-MM-DD.log` (канал `security`, ротация по дням, хранение 14 дней). Обычный журнал приложения находится в `my-site/storage/logs/laravel.log`.

В событиях используется `request-id`. Он возвращается в HTTP-заголовке `X-Request-ID` и выводится на страницах ошибок. Для поиска связанных записей используйте Request ID.

## События журнала

| Событие | Что записывается | Что не записывается |
|---|---|---|
| `login_ok` | имя события, request-id | email, пароль, IP, токены |
| `login_fail` | имя события, request-id | email, пароль, IP, токены |
| `brute_force` | event, `severity=high`, request-id | учётные данные, IP, ПДн |
| `login_throttled` | событие, request-id | учётные данные, IP |
| `data_operation` | событие, HTTP-метод, имя маршрута, request-id (для успешного mutating-запроса) | тело запроса, значения полей, ПДн |
| `access_denied` | событие, HTTP-метод, имя маршрута, request-id | IP, данные пользователя |
| `server_error` | событие, статус, HTTP-метод, имя маршрута, request-id | IP, тело запроса, ПДн |
| `exception` | тип исключения, ограниченные сведения о кадрах трассировки, request-id | параметры запросов, заголовки, пароли, токены |

## Защита входа и алерты

- Лимит по аккаунту: не более 10 неудачных попыток за 5 минут. Ключ лимита — HMAC-хеш аккаунта.
- Лимит по IP: не более 20 неудачных попыток за 5 минут. Ключ лимита — HMAC-хеш IP.
- Для блокировки используется единое сообщение об ошибке входа, не раскрывающее, существует ли аккаунт и верен ли пароль.
- На 10-й неудачной попытке в течение 5 минут для одной комбинации аккаунта и IP записывается алерт `brute_force` с `severity=high`.
- При достижении лимитов записывается `login_throttled`.

`severity=high` означает сигнал о возможном переборе. В журнале проверьте временную последовательность событий и сопоставьте их по Request ID. Журнал не содержит значений аккаунта или IP.

## Страницы ошибок

Для HTTP 403, 404 и 500 предусмотрены пользовательские страницы без технических подробностей. На странице 500 не выводится stack trace, пути к файлам или сообщение исключения. Request ID показывается пользователю для поиска соответствующей записи в журнале. Технические кадры трассировки исключения записываются только в security-журнал.
